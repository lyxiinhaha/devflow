# devflow refactor — 代码重构

**用途：** 专门处理高风险重构场景，强制基线一致性验证，严禁混入业务逻辑变更，完成后自动触发复盘。

---

## 前置条件

- **CRITICAL：现有测试必须全部通过**，否则终止并切换到 `devflow fix`。
- 重构目标符号已明确（函数名、类名、模块路径等）。

不满足时输出：
```
✗ 现有测试未通过，无法开始重构。
  测试失败说明代码存在 Bug，请先执行 devflow fix。
```

---

## ⚠️ 重构禁令

- ❌ 禁止在重构过程中「顺手」修改业务逻辑
- ❌ 禁止在重构过程中添加新功能或新接口
- ❌ 禁止在重构过程中修复 Bug（发现 Bug 记录到 `artifacts/` 留待后续处理）
- ✅ 重构范围严格限定：结构优化、可读性提升、性能改进，不改变外部行为

---

## 执行步骤

### 1. 测试基线验证

运行项目测试套件，确认全部通过。若有失败，**终止重构**：
```
✗ 测试失败，重构已终止。
  请先用 devflow fix 修复以下失败：{失败列表}
```

### 2. 记录重构前基线

对目标符号执行：
```
codegraph_impact  <目标符号>    # 保存所有调用方快照（基线）
codegraph_explore <目标符号>    # 获取被调用方详情
```

将基线数据保存到 `spec/design.md` 的「重构基线」章节（追加，不覆盖）。

### 3. 生成重构计划

列出所有需要同步修改的文件和符号。

若涉及 L0 级别模块 → **强制要求人工审批**后才能继续，不得自行执行。

### 4. 执行重构

按计划执行，禁止超出计划范围。

### 5. 基线一致性验证（核心）

重构完成后对新符号执行：
```
codegraph_impact <重构后符号>
```

**强制断言：** 重构后调用方集合必须与基线**完全一致**。

| 情况 | 处理 |
|------|------|
| 有遗漏（未同步更新的调用方） | 列出遗漏文件，要求修复后重新验证 |
| 有新增（意外引入的新调用方） | 报错，要求用户确认是否符合预期 |

### 6. 再次运行测试

与基线结果对比，确认所有测试仍然通过，无新增失败。

### 7. 强制触发复盘

重构完成且验证通过后，自动调用复盘逻辑，生成经验卡草稿。

---

## 输出

```
✅ 重构完成。
  目标符号：{n} 个
  影响文件：{n} 个
  基线验证：{通过（所有调用方均已同步）| 失败（遗漏 n 处，已列出）}
  测试对比：{全部通过 | 新增失败 n 个}
  L0 人工审批：{是 | 否}

⚠️ 请使用 devflow retrospect 沉淀重构经验。
```
