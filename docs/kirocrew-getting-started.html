Kiro Crew 是什么，和 Kiro IDE 有什么区别

Kiro Crew（本文主角）

独立 App，本质是一个持久化 AI Agent 平台。
有自己的记忆、技能系统、任务调度，对话内容和进度跨重启保留。
适合：长期持续的开发工作，团队知识积累。

Kiro IDE（另一个产品）

AI 集成开发环境，类似 VS Code + AI。
有 Spec 驱动开发、Steering File、Agent Hooks。
适合：在编辑器里直接写代码时用。

ℹ️
这两个是不同的产品，可以同时装，互不影响。DevFlow 对两者都有适配，本手册专讲 Kiro Crew。

1
第一步

启动 Kiro Crew

1

双击打开 /Applications/KiroCrew.app

App 启动后自动在后台运行 Gateway 进程，浏览器会自动打开 http://localhost:5476。

💡
如果浏览器没自动打开，手动访问 http://localhost:5476 即可。Mac App 会在菜单栏显示 Kiro Crew 图标，表示 Gateway 正在运行。
2

用 Kiro 账号登录

首次启动会看到登录界面，点击按钮，浏览器打开授权页面，用你的 Kiro 账号登录即可。

http://localhost:5476
✦
Welcome to Kiro Crew
Sign in with your Kiro account to get started
Sign in with Kiro
ℹ️
没有 Kiro 账号？去 kiro.dev 免费注册。登录是使用 AI 功能的前提，Kiro Crew 本身的 UI 功能（记忆、任务管理等）离线可用。
2
第二步

安装并配置 kiro-cli

Kiro Crew 的 AI 对话能力由 kiro-cli 驱动，必须单独安装。首次使用时控制台会有引导提示。

1

打开终端，安装 kiro-cli

brew install kirocli     # macOS，推荐

# 或手动下载：
curl -fsSL https://kiro.dev/install/cli.sh | sh
💡
安装完后在终端运行 kiro --version 确认安装成功，能看到版本号就行。
2

登录 kiro-cli

kiro login

终端会显示一个验证码，浏览器打开授权页面，确认即可。登录成功后终端显示：

✓ Logged in as your@email.com
3

在 Kiro Crew 控制台验证

回到 http://localhost:5476，点击 Settings（⚙️）→ General，应该能看到 kiro-cli 状态变为绿色 ✅。

Settings → General
kiro-cli ✓ Connected  v1.x.x · your@email.com
Vector Memory Downloading model...  610MB，后台下载，首次需等待
Default Model claude-sonnet-4-5
⚠️
首次启动会在后台下载 610MB 的向量嵌入模型（用于语义搜索），这需要几分钟。下载完成前记忆搜索用关键词模式，下载完成后自动升级为语义搜索，不需要你操作任何东西。

3

工具调用审批

当 AI 要做某些操作（写文件、运行命令）时，会出现审批弹框，需要你点击批准或拒绝。

⚠️ Tool Approval Required
fs_write → /Users/me/project/.devflow/workspace.json
✓ Approve Trust (always) ✗ Reject
选项含义
Approve只批准这一次
Trust这类操作以后自动批准（推荐对读文件/写 .devflow/ 选这个）
Reject拒绝，AI 会尝试其他方式

常见问题

小白容易遇到的问题和解决

Q

说了 devflow start，AI 说「我不知道这个命令」

Skill 没有加载。检查步骤：

# 1. 确认 Skill 文件存在
ls ~/.kiro/crew/skills/devflow/SKILL.md

# 如果文件不存在，重新安装
git clone https://github.com/lyxiinnaha/devflow.git devflow-tmp \
  && bash devflow-tmp/install.sh --platform kirocrew \
  && rm -rf devflow-tmp

# 2. 重启 Kiro Crew
Q

AI 找不到 .devflow/commands/ 文件

Kiro Crew 需要知道项目在哪里。在对话里说：

我的项目路径是 /Users/me/projects/hssa

或者在 Settings → Chat → Workspace 里设置默认工作目录。

Q

工具审批弹框太烦，能不能不弹？

对常用操作点 Trust（而不是 Approve），以后这类操作自动批准。或者在 Settings → Chat → Default to Autopilot Mode 开启全自动（所有操作自动批准，谨慎使用）。

Q

Task Runner 中途失败了怎么办

在对话里说：

任务中途失败了，帮我从 T-04 继续

或者重新 run tasks.md，Task Runner 会自动跳过已完成的任务。

Q

关闭 App 再打开，之前的对话还在吗

在。Kiro Crew 的所有对话、记忆、任务状态都持久化在本地 ~/.kiro/crew/，关闭 App 不会丢失。重新打开后找到对应会话点进去即可继续。

DevFlow 的工作项进度也存在项目目录的 .devflow/work-items/，同样跨会话保留。

Q

多个需求同时进行怎么管理

每个需求开一个 Kiro Crew 对话标签，用 devflow switch 切换焦点：

devflow list

⏸ 20260820-ConditionalOrder  designing
