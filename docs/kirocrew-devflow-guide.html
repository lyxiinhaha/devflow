整体架构

DevFlow 在 Kiro Crew 里的三层集成

Layer 1

Skills 命令路由

说「devflow start」等命令，Kiro Crew 自动触发 DevFlow Skill，读取命令文件执行 SDLC 流程。

Layer 2

Task Runner 编码执行

devflow plan 生成 tasks.md 后，交给 Kiro Crew Task Runner 无人值守执行，支持断点续跑。

Layer 3

Knowledge Library

经验卡文件夹加入 Kiro Crew 知识图谱，自然语言查询历史踩坑，向量检索比关键词更准。

第一步

安装 Kiro Crew 和 DevFlow

1-A　安装 Kiro Crew

如果还没有安装 Kiro Crew，在终端运行一行命令：

curl -fsSL https://download.crew.kiro.dev/cli.sh | sh

安装完成后启动 Gateway，打开浏览器访问控制台：

kirocrew service start          # 后台启动 Gateway
# 浏览器打开：http://localhost:5476

1-B　安装 DevFlow

在项目根目录执行，选择 Kiro Crew 平台：

git clone https://github.com/lyxiinnaha/devflow.git devflow-tmp \
  && bash devflow-tmp/install.sh --platform kirocrew \
  && rm -rf devflow-tmp

安装脚本会做三件事：

1
命令文件 → 复制 20 个命令文件到项目的 .devflow/commands/
这些文件是 DevFlow 的核心，定义了每个命令的执行逻辑
2
DevFlow Skill → 安装到 ~/.kiro/crew/skills/devflow/SKILL.md
全局安装，所有项目通用，Kiro Crew 启动时自动加载
3
知识库模板 → 初始化 .devflow/config/templates/knowledge/
包含 20 张通用经验卡模板，项目经验会逐步追加进来
ℹ️
安装完成后重启 Kiro Crew Gateway（kirocrew service restart），让新 Skill 生效。 或在控制台 Overview → Skills 页面手动点击 Refresh。

{

    "auto_approve_tools": ["read", "Reading *", "fs_write", "Running: ./gradlew *"]
  }
}

2

AI 执行四阶段 CodeGraph 根因分析

devflow fix 点击发单后 Dialog 崩溃，IllegalStateException: Can not perform this action after onSaveInstanceState
Stage 1：入口定位
ShareOrderButton.onClick() → DialogManager.show()

Stage 2：调用链追踪
DialogManager.show(fm, tag) → super.show(manager, tag)
↑ 此处 FragmentManager 在 onSaveInstanceState 后已提交，直接调用崩溃

Stage 3：爆炸半径
直接影响：ShareOrderFragment · OrderListFragment（2 处调用）
MEDIUM 级别，继续修复

Stage 4：原子修复方案
将 super.show() 替换为安全重载 showAllowingStateLoss()
3

人工验证门禁 — AI 等你确认再提交

修复已完成，diff 如下：

- super.show(fragmentManager, tag)
+ showAllowingStateLoss(fragmentManager, tag)

请手动验证后回复「验证通过」，我再提交。
验证通过，提交吧
✅ 已提交。强制进入复盘环节...
⚠️
这是 DevFlow 的人工验证门禁——修复再快，AI 也不会自动 commit，必须等人确认。防止 AI 自作主张提交未经验证的修复。
