## 快速上手

### 安装插件

```bash
claude plugins install devflow
```

### 初始化项目（每个项目只需一次）

```
devflow init
```

AI 会自动完成：
1. 检查并配置 CodeGraph（建立代码索引）
2. 检查并授权 Meegle（已安装则验证授权，否则引导安装）
3. 建立 `.devflow/` 目录结构
4. 写入 `.gitignore`（自动排除 `.devflow/` 和 `.codegraph/`）
5. 确认项目安全分级（L0 / L1 / L2）
6. 配置 Meegle 项目空间（可选）

## 最短使用路径

### 需求开发：标准路径（7 步，3 次等待）

```
devflow start "用户头像上传"     ← 自动进入需求收集模式

[逐段发送需求内容]              ← 每段立即解析，即时追问
"就这些了"                      ← 触发最终分析

devflow design                  ← ⏸ 等待：技术决策确认

devflow plan                    ← 自动，无需确认

devflow code                    ← ⏸ 等待：选择执行范围（输入 2 全部执行）

devflow review                  ← 自动扫描

devflow retrospect              ← ⏸ 等待：确认经验卡入库（自动触发）
```

**你只需说 3 次话：确认技术决策、选择执行范围、确认经验卡。**

### 快速路径（根据复杂度自动选择）

`devflow quick` 会分析需求后自动判断走哪条路：

**极简**（改 1-2 个文件）：分析 → 直接编码，**1 条命令搞定**
```
devflow quick 修改登录页文案「立即登录」改为「登录」
← AI 分析后：影响 1 个文件，直接编码，完成后自动 review
```

**快速**（改 3-5 个文件）：分析 → 内联方案确认 → 编码，**跳过 design 和 plan**
```
devflow quick 详情页右上角加分享按钮 https://figma.com/...
← AI 分析后：影响 4 个文件
⚙️ 快速路径确认，改动文件和关键逻辑已列出，继续编码？

devflow review                  ← 自动
devflow retrospect              ← ⏸ 确认经验卡
```

**完整**（改 > 5 个文件或涉及架构）：分析完成，提示转标准流程
```
devflow quick 重构账户模块状态管理
← AI：影响 12 个符号，建议 devflow design → ...
```

**适用场景：** 文案修改、配置项调整、小 UI 改动、接入已有接口。复杂需求自动升级到完整流程，不会漏掉该走的步骤。

---

### Bug 修复：1 条命令，1 次等待

```
devflow fix https://project.feishu.cn/...

[AI 自动读取 issue、分析根因、修复代码]

"第 1 条验证通过"               ← ⏸ 唯一一次等待：人工验证后提交

[devflow retrospect 自动触发]
```

## 需求开发完整流程

### Step 1：创建工作项

```
devflow start feature 用户头像上传 支持从相册选取、裁剪、预览，保存到 CDN
```

工作项创建完成后，**自动进入需求收集模式（Intake Mode）**，后续每段输入立即处理。

---

### Step 2：逐段发送需求（Intake Mode）

Intake Mode 下，你可以用任意顺序发送以下内容，每段收到后立即解析：

#### 发送文字描述
```
用户可以在个人资料页点击头像修改，支持从相册选取照片
```
AI 立即回复：
```
📥 #1 已解析
  功能点：个人资料页头像入口 → 相册选取
  ⚠️ 选取后直接使用，还是需要裁剪步骤？
```

#### 发送 Figma 链接
```
https://www.figma.com/design/ABC123/...?node-id=1-2
```
AI 立即读取设计稿，提取页面层级、组件、文案、交互状态，并与已有文字交叉核验：
```
🔍 读取 Figma 中...
📥 #2 已解析
  页面：个人资料页、裁剪弹窗、加载态
  文案：「更换头像」「重新选取」「保存」
  ⚠️ Figma 中有「删除头像」按钮，PRD 未提及，是否在本期范围？
```

#### 发送 YApi 接口链接
```
https://yapi.hszq8.com/project/123/interface/api/456
```
AI 立即读取接口定义，核验字段与需求描述是否匹配：
```
🔍 读取接口中...
📥 #3 已解析
  接口：POST /user/avatar/upload
  字段：file(binary), type(enum: jpg/png/webp)
  ⚠️ 接口无文件大小限制字段，PRD 提到 10MB，客户端校验还是服务端校验？
```

#### 发送图片/截图
直接粘贴，AI 保存到 `artifacts/` 并识别可见内容。

---

### Step 3：触发最终分析

收集完所有需求后，发送结束信号：

```
就这些了
```

AI 执行最终一致性检查（文字 vs Figma vs 接口），通过 CodeGraph 核验现有代码模块，**主动反查该模块关联的 YApi 接口**（不依赖 PRD 是否提供），生成完整 `spec/requirement.md`。

---

### Step 4：技术设计

```
devflow design
```

**自动完成（无需干预）：**
- 从 `spec/requirement.md` 读取 UI 规范和接口定义（不重复读 Figma）
- 召回知识库中相关模块的 Bug 经验，转化为设计约束
- CodeGraph 爆炸半径评估（HIGH/CRITICAL 风险会暂停）
- 生成内部设计文档（`spec/design.md`）+ 对外技术方案（`spec/tech-design-doc.md`）

**需要你确认（遇到技术决策时当场追问）：**
```
⚙️ 技术决策 #1
  场景：图片压缩在哪里执行？
  方案 A：客户端压缩后上传（节省带宽，体验更流畅）
  方案 B：服务端压缩（客户端逻辑简单，但上传流量大）
  建议：方案 A
  请确认或选择其他方案：
```

---

### Step 5：任务拆解

```
devflow plan
```

完全自动，**无需任何确认**，直接输出标准格式的 `tasks.md`：
- 按模块分组
- 每个任务含：描述 / 涉及文件 / 技术要求 / 验收标准 / 依赖关系
- 高风险任务自动标注 `⚠️ [CodeGraph 前置检查]`
- 召回知识库经验转化为「编码禁令」

---

### Step 6：编码

```
devflow code
```

AI 先展示未完成任务列表，询问执行范围：
```
请选择本次执行范围：
1. 只完成第一个任务
2. 完成全部任务
3. 执行到指定编号
```

输入 `2` 后全自动执行，期间只有一种情况会打断你：
```
⚠️ T005 涉及 UserProfileRepository（HIGH 风险，11 个调用方）
   是否确认继续？
```

每个任务完成后自动运行 lint/test，任务状态实时标记。

---

### Step 7：代码审查

```
devflow review
```

全自动，四维度扫描（质量 / 安全 / 性能 / 反模式），输出审查报告：

```
### Code Review Report
- Status: APPROVED
- Critical Issues: 0
- Minor Issues: 1
  - src/avatar/ViewModel.kt:45: 未处理网络超时
```

发现 CRITICAL 问题时输出 `BLOCKED`，必须修复后才能继续。

---

### Step 8：复盘（自动触发）

review 完成后自动触发，展示经验卡草稿，确认后入库：

```
### Retrospect
- Type: Feature
- Card ID: KB-021
- Root Cause: 图片上传未处理弱网重试
- Prevention: 上传接口必须实现幂等键 + 重试上限 3 次
```

确认入库，Meegle 工作项自动关闭。

## Bug 修复流程

### 支持的输入格式

| 格式 | 示例 |
|------|------|
| Meegle issue 链接 | `devflow fix https://project.feishu.cn/xxx/issue/detail/123` |
| Meegle 视图链接（批量） | `devflow fix https://project.feishu.cn/xxx/issueView/...` |
| Meegle 工作项 ID | `devflow fix 12345678` |
| 直接描述 | `devflow fix 登录后页面白屏，点击头像必现` |

### 三种执行模式

| 模式 | 触发条件 | 行为 |
|------|---------|------|
| **分析模式** | 不含修复意图 | 只分析，不改代码 |
| **修复模式** | 含「修复/fix/解决」 | 分析 + 最小修复 + 等待人工验证 |
| **重排查模式** | 含「重开/验证不通过/还有问题/再看看」 | 读历史清单 + 加调试日志 + 清理后提交 |

### 修复准入门禁

分析评分 < 90 分时**拒绝进入修复模式**，必须补充信息：

| 维度 | 权重 |
|------|------|
| 信息完整性（仓库/分支/现象/预期） | 20 |
| 根因定位质量（有代码证据） | 30 |
| 修复方案质量（最小、安全、可执行） | 25 |
| 影响范围与风险说明 | 15 |
| 验证方案可执行性 | 10 |

### 产物

每个 Bug 生成独立修复清单：
```
.bugfix-records/260805/12345678-登录白屏-bug修复清单.md
```

## 17 个命令详解

### 主线流程

#### `devflow init` — 初始化工作区
**何时用：** 项目首次使用 DevFlow，或 `.devflow/` 目录不存在时（`devflow start` 会自动触发）。

**自动完成：** CodeGraph 安装与索引、Meegle 授权检查、目录创建、`.gitignore` 写入。

**需要你回答：** 项目安全分级（L0/L1/L2）、Meegle 项目空间名（可选）。

---

#### `devflow start` — 创建工作项
**何时用：** 开始一个新需求/功能/Bug/重构时。

**输入格式：** `devflow start {类型} {标题} {描述}`
- 类型：`feature` / `bug` / `tech` / `refactor`
- 不传类型时 AI 自动推断

**自动完成：** 创建工作项目录、初始化状态机、可选同步 Meegle、**进入 Intake Mode**。

---

#### `devflow quick` — 快速需求
**何时用：** 需求描述清晰的小改动，尤其是 1-2 个文件的极简修改。

**输入格式：** `devflow quick {需求描述} [Figma 链接] [YApi 链接]`

**三条执行路径（自动判断，无需手动选择）：**

| 路径 | 触发条件 | 跳过步骤 |
|------|---------|---------|
| **极简** | 影响 ≤ 3 个符号 | 跳过 design + plan，直接编码 |
| **快速** | 影响 4-10 个符号，无新增接口 | 跳过 design + plan，内联方案后编码 |
| **完整** | 影响 > 10 个符号，或需新增接口/模块 | 自动转 `devflow design` |

极简路径：**1 条命令完成整个需求**（分析 + 编码 + review 全自动）。
快速路径：AI 列出改动文件和关键逻辑，用户确认一次后直接编码。
完整路径：需求分析已完成，直接进 `devflow design` 不用重新分析。

---

#### `devflow analyze` — 需求分析（Intake Mode）
**何时用：** `devflow start` 后自动激活，也可独立调用。

**Intake Mode 支持的输入：**

| 输入类型 | 处理方式 | 回复格式 |
|---------|---------|---------|
| 文字描述 | 提取功能点，发现歧义即时追问 | `📥 #N 已解析` |
| Figma 链接 | Figma Desktop MCP 立即读取，交叉核验 | `🔍 读取 Figma 中...` |
| YApi/接口链接 | WebFetch 立即读取，字段交叉核验 | `🔍 读取接口中...` |
| 图片/截图 | 保存 artifacts/，识别可见内容 | `📥 #N 图片已保存` |

**结束信号：** `就这些了` / `完了` / `devflow analyze`

**Finalize 阶段自动完成：** 三方一致性检查（文字 vs Figma vs 接口）、CodeGraph 现有模块核验、**主动反查现有模块关联的 YApi 接口**、生成完整 `spec/requirement.md`。

---

#### `devflow design` — 技术设计
**何时用：** 需求分析完成后。

**不需要重复读取：** Figma 和接口数据已在 analyze 阶段读入 `spec/requirement.md`，design 直接使用。

**自动完成：**
- Bug 经验加载，命中卡的反模式转化为设计约束
- CodeGraph 爆炸半径评估（HIGH 暂停确认，CRITICAL 强制停止）
- 平台专项设计（iOS `design_ios.md` / Android `design_android.md` / KMP `design_kmp.md`）
- 接口变更同步到 `spec/api.md`
- 对外技术方案文档 `spec/tech-design-doc.md`（含功能范围、模块依赖、接口清单、异常处理）

**遇到技术决策当场追问：** 多方案选择时给出 A/B 对比 + AI 建议，确认后写入文档。

**设计文档冻结：** 用户确认后文档锁定，编码阶段不得修改，发现问题须触发 `devflow change`。

---

#### `devflow estimate` — 工作量估算
**何时用：** 需要给出工时 ETA 时，可选步骤。

**估算模型：**
```
基础工时 × 复杂度乘数（LOW:1.0 / MEDIUM:1.5 / HIGH:2.5）
× L0 储备（×1.2）× 历史 Bug 密度（高密度模块 ×1.25）
```

输出乐观 / 期望 / 悲观三点估算，明确排除 QA/部署/外部等待时间。

可更新 Meegle 节点排期。

---

#### `devflow plan` — 任务拆解
**何时用：** 技术设计完成后。

**完全自动，无需确认。** 输出 `tasks.md`，格式：
```markdown
- [ ] **[T001] 任务名称**
  - Description: 做什么、在哪个文件
  - Files: src/avatar/AvatarViewModel.kt
  - Technical Requirements: 禁止 float 处理文件大小
  - Acceptance Criteria:
    - [ ] 验收标准1
    - [ ] 来自 Bug 经验卡的验收项
  - Dependencies: None
  - Risk: ⚠️ [CodeGraph 前置检查]
```

---

#### `devflow code` — 执行编码
**何时用：** 任务拆解完成后。

**编码禁令（AI 自动遵守）：**
- 禁止修改当前任务范围外的文件
- 禁止在编码阶段修改 `spec/design.md`
- 禁止未批准的重构
- L0 模块只提供代码建议，不直接写入

**执行流程：** 选择范围 → CodeGraph 前置检查 → 编码 → lint/test → 标记完成 → 下一个任务。

---

#### `devflow review` — 代码审查
**何时用：** 编码完成后，自动执行。

**四维度：** 代码质量 / 安全（注入/越权/敏感数据）/ 性能（N+1/内存泄漏）/ 反模式扫描

**CRITICAL 问题 → 输出 BLOCKED，必须修复后才能合并。**

---

#### `devflow retrospect` — 强制复盘
**何时用：** 由 `fix` / `review` / `refactor` 自动触发，也可手动调用。

**按工作项类型选择模板：** Bug Fix（根因/检测盲区/防复发）/ Feature（技术权衡/技术债）/ Refactor（重构收益/后续建议）

**去重检查：** 写入前检查知识库，避免重复经验卡。

---

### Bug 修复支线

#### `devflow fix` — Bug 修复
**何时用：** 收到 Bug 报告时，支持 Meegle issue 链接、ID、直接描述。

详见 [Bug 修复流程](#bug-修复流程)。

---

### 重构专线

#### `devflow refactor` — 代码重构
**何时用：** 需要提取函数、移动模块、重命名接口等高风险改动时。

**强制前置：** 现有测试必须全部通过，否则终止，提示先 `devflow fix`。

**核心保障：** 重构前记录 CodeGraph 基线快照，重构后强制断言调用方集合与基线完全一致，有遗漏则报错。

---

### 辅助工具

#### `devflow continue` — 恢复进度
**何时用：** 新开会话、`/clear` 后，或中断开发后重新开始。

优先读取 `progress.md` 的 Context Checkpoint（不重读所有长文档），展示当前状态和 Meegle 最新状态，推荐下一步命令。

---

#### `devflow switch` — 切换工作项
**何时用：** 同时处理多个需求，需要在之间切换时。

列出所有工作项（Active / Paused / Completed），切换后自动执行 `continue` 恢复上下文。

---

#### `devflow list` — 查看工作项列表
**何时用：** 需要看当前所有需求的进度状态时。

按 Active / Paused / Completed 分组，显示类型、状态、优先级、最后更新时间，可选同步 Meegle 状态（加 `--sync`）。

---

#### `devflow change` — 需求变更
**何时用：** 开发中途收到需求调整时。

**变更分级：**
- Minor（UI 文案、单一字段）→ 轻量回退
- Major（架构级影响）→ 回退到 `analyzing`，重走设计流程

受影响的已完成任务标记「需返工」，变更历史写入 `progress.md` 保留可追溯性。

---

#### `devflow knowledge` — 团队知识库
**何时用：** 查找历史 Bug 经验、查看知识库健康状态，或手动添加经验时。

**查询语法：**
```
devflow knowledge query tag=security
devflow knowledge query module=payment
devflow knowledge query token 登录 过期
devflow knowledge check          ← 健康检查
devflow knowledge export         ← 导出 JSON
```

内置 20 条种子经验卡（覆盖异步竞态、精度、缓存、安全、跨域等高频问题）。

---

#### `devflow sync` — 团队 AI 文件同步

**何时用：**
- 首次在项目中使用 devflow，需要安装团队公共 skill
- devflow 插件升级后，将新版 skill 同步到各项目
- 新成员配置本地 AI 工具环境

```
devflow sync
```

**自动完成：**
1. 将 devflow 插件包 `ai-files/skills/` 中的团队公共 skill 复制到当前项目 `.ai/skills/`
2. 在 `.claude/skills/`、`.codex/skills/` 下创建软链接（指向 `.ai/skills/`）
3. 在 `.gitignore` 中维护个人 AI 配置忽略规则（防止 `.claude/`、`.codex/` 误提交）
4. 将已被 Git 跟踪的个人 AI 配置从 Git index 移除（本地文件保留）

**与 `devflow knowledge` 的区别：**

| | `devflow sync` | `devflow knowledge` |
|---|---|---|
| 管理内容 | Skill / Agent 文件（工具本身） | Bug 经验卡（CSV 数据） |
| 触发时机 | 手动，环境初始化时 | 自动召回 / 复盘后写入 |
| 类比 | 「安装团队工具」 | 「查阅防坑手册」 |

---

#### `devflow onboard` — 代码库入职导览
**何时用：** 新成员熟悉模块，或自己接手陌生模块时。

```
devflow onboard payment 模块
devflow onboard 用户认证流程
```

输出《模块架构导览报告》：核心组件、数据流向、关键依赖、历史 Bug 热点、Meegle 近期工作项。

## 集成工具说明

### CodeGraph（必须）

**作用：** 构建项目代码知识图谱，提供符号搜索、调用链追踪、爆炸半径评估能力。

**使用场景：**
- `analyze`：核验需求中提到的模块/类是否真实存在
- `analyze`：自动反查现有模块关联的 YApi 接口
- `design`：评估每个改动点的影响面（直接/间接调用方）
- `code`：高风险任务编码前的前置检查
- `fix`：Bug 根因定位和修复后影响面验证
- `refactor`：重构前基线快照和重构后一致性断言

**配置：** `devflow init` 自动安装并建立索引，大型工程支持后台运行。

---

### Meegle（可选）

**作用：** 飞书项目管理，工作项全生命周期联动。

**各阶段联动：**

| DevFlow 阶段 | Meegle 操作 |
|------------|-----------|
| `start` | 创建工作项（可选） |
| `analyze` | 添加需求分析评论 |
| `design` | 添加设计完成评论 |
| `code` | 流转至「开发中」 |
| `fix` | 读取 Bug 详情，流转至「已修复」，添加修复说明 |
| `review` | 流转至「待合并」，添加审查结论 |
| `retrospect` | 关闭工作项 |

**配置：** 已安装则 `devflow init` 只验证授权，未安装则引导安装。

---

### Figma Desktop MCP（可选）

**作用：** 需求分析阶段读取设计稿，提取页面层级、组件、状态机、文案。

**使用场景：** `analyze` 阶段收到 Figma 链接时自动调用，与文字需求交叉核验（PRD 未提及的元素即时追问）。`design` 阶段需求文档中 UI 规范不完整时补充读取。

**工具：**
| 工具 | 用途 |
|------|------|
| `get_figma_data(fileKey, nodeId)` | 读取节点结构、属性、组件层级 |
| `get_screenshot(fileKey, nodeId)` | 获取视觉截图，辅助理解布局 |
| `get_metadata(fileKey)` | 获取文件级元数据 |

**配置：** 安装 Claude Code 官方 figma 插件即可，无需额外配置：
```bash
claude plugins install figma
```

**降级链条：**
1. Figma Desktop MCP（首选，`figma` 插件）
2. Framelink MCP（`figma-developer-mcp`，项目 `.mcp.json` 中配置）
3. 均不可用时：链接记录到文档，标注「待手动核验」，不阻塞流程

---

### YApi（可选）

**作用：** 读取接口定义，核验字段与需求描述是否一致。

**使用场景：**
- `analyze`：收到 YApi 接口链接时读取接口详情
- `analyze`（Finalize）：CodeGraph 找到现有模块后，**主动反查该模块关联的接口**
- `design`：`spec/requirement.md` 接口章节为空时补充读取

**调用方式：** WebFetch 直接访问 `yapi.hszq8.com`（无需 MCP）
```
GET https://yapi.hszq8.com/api/interface/get?id={接口ID}
GET https://yapi.hszq8.com/api/interface/list?project_id={pid}
```

降级：YApi 不可用时使用 Apifox MCP（「API 文档」）。

## 常见场景

### 新会话/clear 后如何恢复

```
devflow continue
```

AI 读取 Context Checkpoint，展示当前状态和推荐下一步，通常 10 秒内恢复完毕。

---

### 开发中途收到需求变更

```
devflow change 新增手机号登录方式，去掉邮箱登录
```

AI 判断变更级别（Minor/Major），强制回退状态机，标记受影响任务，重新评估 CodeGraph 影响面。

---

### 需要同时处理多个需求

```
devflow list                    ← 查看所有工作项
devflow switch                  ← 切换到另一个需求
devflow continue                ← 恢复该需求上下文
```

---

### 接手陌生模块

```
devflow onboard UserService 模块
```

---

### 查找历史 Bug 经验

```
devflow knowledge query token 过期
devflow knowledge query module=payment severity=CRITICAL
```

---

### 安全分级说明

| 级别 | 适用模块 | AI 权限 |
|------|---------|---------|
| **L0** | 核心交易/支付/账户/权限 | 只提供代码建议，禁止直接写入文件，必须人工审查 |
| **L1** | 业务核心模块（非交易） | AI 可辅助，HIGH/CRITICAL 风险必须人工确认 |
| **L2** | 基础设施/工具/UI 组件 | AI 全量辅助，LOW/MEDIUM 自动放行 |

## 产物文件说明

每个工作项在 `.devflow/work-items/{YYYYMMDD}-{slug}/` 下生成：

| 文件 | 内容 | 生成阶段 |
|------|------|---------|
| `meta.json` | 状态机、安全分级、Meegle ID | start |
| `context/sanitized.md` | 需求原始输入（脱敏版） | start / analyze |
| `spec/requirement.md` | 结构化需求文档（最终版） | analyze |
| `spec/design.md` | 内部技术设计文档（冻结） | design |
| `spec/tech-design-doc.md` | 对外技术方案文档 | design |
| `spec/api.md` | 接口变更记录 | design |
| `tasks.md` | 原子任务清单 | plan |
| `progress.md` | Context Checkpoint + 操作日志 | 全程更新 |
| `review.md` | 代码审查报告 | review |
| `artifacts/` | 截图、参考资料 | analyze |

Bug 修复产物在 `.bugfix-records/{yyMMdd}/` 下独立存放。
